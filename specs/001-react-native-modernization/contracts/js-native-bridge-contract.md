# JS-Native Bridge Contract (React Native Frontend)

## Purpose

Defines the frontend-to-native interface required to preserve AndrOBD functionality during React Native UI migration.

## Contract Surface

## Connection APIs

- `connect(transportType, options) -> Promise<ConnectionSession>`
- `disconnect(sessionId) -> Promise<{ status }>`
- `getConnectionState() -> Promise<ConnectionSession>`

### Rules

- Must support transport categories currently supported by the app.
- Must emit deterministic error codes for unsupported transport/capability states.

## Diagnostic APIs

- `runDiagnosticAction(sessionId, serviceType, params) -> Promise<DiagnosticServiceAction>`
- `clearFaultCodes(sessionId, confirmationToken) -> Promise<DiagnosticServiceAction>`

### Rules

- `clearFaultCodes` requires explicit confirmation token generated by UI confirmation action.
- Unsupported services return `resultStatus=unsupported`, not transport-level failure.

## Live Data APIs

- `startLiveData(sessionId, selectedPids) -> Promise<{ streamId }>`
- `stopLiveData(streamId) -> Promise<{ status }>`
- Event channel `onLiveDataSample(streamId, sample)`

### Rules

- Event payload must include timestamp, key, value, unit (if available), quality flag.
- Stream shutdown on disconnect must produce terminal event for UI cleanup.

## Recording APIs

- `startRecording(streamId, metadata) -> Promise<{ recordingId }>`
- `stopRecording(recordingId) -> Promise<MeasurementRecording>`
- `loadRecording(fileUri) -> Promise<MeasurementRecording>`
- `exportRecording(recordingId, format='legacy') -> Promise<{ fileUri }>`

### Rules

- Legacy recordings must load without manual migration.
- Export in legacy-compatible output must be supported even when internal storage format changes.

## Settings + Plugin APIs

- `getPreferences() -> Promise<UserPreferenceProfile>`
- `setPreference(key, value) -> Promise<{ status }>`
- `listPlugins() -> Promise<ExtensionModuleState[]>`
- `invokePluginAction(moduleId, action, payload) -> Promise<{ status, data }>`

### Rules

- Plugin failures must be surfaced with structured error object and user-safe message.

## Observability Contract

- Frontend must emit structured log events with correlation IDs for:
  - Connection attempt + result
  - Diagnostic action start + result
  - Plugin init/action failures
- Metrics sink must provide:
  - `connection_success_rate`
  - `diagnostic_action_failure_rate`
  - `crash_free_sessions`
